# Интерьер по правилам

Цель — умение отрисовать ЛЮБОЙ интерьер реалистично, а не одну комнату. Работаем системой, не «на глаз».

## Правило пользователя (16.10): перед КАЖДЫМ прогоном
1. Проверить всё: код (py_compile), имена узлов/режимов/файлов сверить с источником (не по памяти), пути, видеокарта свободна.
2. Посмотреть прошлый результат, записать уроки (ниже, в «Уроки»).
3. Исправить ошибки. Только потом запускать.

## Порядок работы
1. **Паспорт модели** (до того как ставить в сцену): `tools/interior/library.json` + `passport.py`.
   Новая модель → запись в library.json (cat, file, parts по ТОЧНЫМ именам в файле, hide, paint) →
   `blender -b -P tools/interior/passport.py -- D:/pol-ai/passports <ключ>` → посмотреть миниатюры листом
   (перёд должен смотреть на нас). Ошибся автоопределитель — `"front": угол, "front_manual": true`.
2. **Расстановка — по базе правил**: `D:\pol-ai\vault\База — дизайн гостиной.md` (чек-лист в конце).
   Ставить через `assets.put(key, x, y, facing)` — facing это куда смотрит ПЕРЁД (радианы, 0 = +X, π/2 = +Y).
3. **Проверка без рендера**: план сверху с размерами и нарушениями (проходы, расстояния, куда смотрит).
4. **Быстрый черновик**: `blender -b -P tools/interior/build.py -- <layout.json> <папка> 32 fast` (Eevee, ~1 мин; любая комната по файлу), критик-агент сверяет с чек-листом. Слабое пользователю не показывать.
5. **Чистовой**: `room_living.py ... 256 bk` → `ai_realism.py` → `floor_tex.py` + `floor_render.py` (пол по декору) → `floor_composite.py`.
6. **После каждой тренировки** — дописать уроки ниже.

## Уроки (на чём обжигались)
- Подлокотник выше спинки на торцах → перёд дивана ищем только на ДЛИННЫХ сторонах.
- Имена в .blend: «plant» и «plant.002» — РАЗНЫЕ предметы; при повторной загрузке появляются .001 → сверять по имени в файле (src_name), не по началу строки.
- Не «расплющивать» вложенность моделей (setting matrix_world детям) — искажается масштаб (шторы стали 11 м). К пустышке цеплять только верхние объекты.
- В стартовой сцене Blender есть куб 2 м, свет, камера — удалять всё перед работой (`bpy.data.objects`).
- Если ставишь вещь «куда-то» — спроси себя, где её ставят в жизни (подсвечники — не на пол, корзина — не посреди комнаты, плед — свисает, а не лежит доской).
- Не менять сразу много: пользователь сказал «стало только хуже», когда убрал большое растение и передвинул торшер. Менять по 1–2 вещи и сравнивать рядом.
- Видеокарта может быть занята (игры): ошибка «out of GPU memory» → третий аргумент `cpu` в room_living.py, или попросить закрыть игру; `texture_limit_render = '2048'`.
- cv2 не читает пути с кириллицей → `cv2.imdecode(np.fromfile(...))` / `imencode(...).tofile(...)`.
- Скачивание BlenderKit: `tools/blender/bk_download.py` (ключ из аддона, не печатать); последний шаг — заголовок User-Agent: Mozilla.
- Вставляя комментарий в строку с «a; b», проверь, что b не ушло в комментарий (так пропали шумоподавление и цвет солнца — нашёл проверяющий).
- Цвет пола проверять цифрами против фото декора (альбедо = пол / белый пол), подгонка в floor_composite.py.

## Уроки тренировок по эталонам (D:/pol-ai/refs, описания — vault «Эталоны гостиных»)
- ref3 (узкая гостиная, диван лицом к ТВ): камера смотрит ВДОЛЬ комнаты на окно/дверь, почти по центру — `aim_camera` ДО расстановки (иначе поиск мест считает по другому кадру).
- Передний план — НИЗКИЙ предмет (пуф/табурет ≤ 0,5 м) у края кадра; высокое кресло перед камерой закрывает полкадра. Правило plan.py «загораживает кадр»: высота > 0,6 м, ближе 1,8 м, в центральных ±15°.
- В тесной комнате не впихивать: нет чистого места — предмет не ставим (best_spot → None). На эталоне в узкой комнате тоже нет кресла.
- Фото риелторов (пустые комнаты) — плохие эталоны: мёртвость дают пустота и стерильность, а не графика.
- Одна схема расстановки не годится для всех комнат: arrange.py — схемы `back_wall` (диван у дальней стены) и `side_tv` (диван вдоль боковой стены лицом к ТВ).
- Ещё не сделано (по сравнению с ref3): стайлинг (плед/овчина, подушки разных цветов, вещи на столике, растение в корзине), низкая тумба, цвет стен и тёплый свет.

- Нейросеть подменяет предметы (картина → другое фото, ваза → латунь, плед исчезает): второй поводок по контурам (union ControlNet, режим 'canny/lineart/anime_lineart/mlsd'), карта силы по меткам pass_index (картина 2, мелочи 3) + DifferentialDiffusion; картина вставляется обратно из Blender.

- Запуск только через `tools/interior/run_full.py` (сам проверяет: код, «код в комментарии», план, файлы, видеокарта; `--check` — без рендера).
- «Код в комментарии» случился ТРИЖДЫ (шумоподавление, солнце, экспозиция — прогон 5 был тёмным из-за этого). Теперь ловит run_full.py автоматически. Правки делать отдельными строками.
- Подсказка нейросети — из расстановки (`desc` в паспортах), не вручную: устаревший текст «abstract art» подменял картину. В NEG не писать «painting/illustration» — нейросеть убирает картины.
- Цветокоррекция по замеру (grade.py): медиана яркости 110–130, баланс по светлым нейтральным местам; прогон 5 был 70 и R/B 1,5.
- Обрезанный краем ДАЛЬНИЙ предмет — ошибка (торшер); близкий у края — «обрамление», можно (`edge_ok`). Проверка — plan.frame_check.
- Вещи на столе: каждая ≤ 1/3 длины стола, вместе ≤ 60 % столешницы.
- После прогона — агент `critic` по «Критерии реализма» (vault). Пользователь оценивает строже автора (8 → 7).
